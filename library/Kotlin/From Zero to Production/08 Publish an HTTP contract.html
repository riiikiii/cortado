Establish a wire contract

A feed client assigns a UUID to an observation and sends the price as an integer. The same observation may arrive again after a timeout. The server needs enough information to distinguish a harmless retry from accidental reuse of that UUID with a different payload.

Request Domain decision HTTP result
PUT unused identifier with valid price Create 201
PUT same identifier and identical quote Replay 204
PUT same identifier and different valid quote Conflict 409
PUT invalid price or malformed UUID Reject input 400
GET unknown identifier No persisted value 404

Spring matches the verb and path, converts the path segment to a UUID, reads JSON through Jackson and then calls the method. A syntactically bad UUID fails before the method starts. Input has nullable fields so missing or explicit null values can be treated as a boundary error. The required constructor values in Quote are non-null. The small try block covers conversion only. An infrastructure exception in record occurs outside it. That keeps an unavailable database from being reported as a bad client price.

Constructor injection makes the dependency visible. The controller can be instantiated directly in a unit test with a fake QuoteStore. Spring discovers a single concrete implementation in the application's package tree and injects it at startup. The Kotlin Jackson module supports Kotlin constructor metadata. The application disables fractional-to-integral conversion and scalar coercion so JSON 1.5 is rejected for the ticks field. Test actual JSON with the HTTP stack. Direct Kotlin method calls cannot reveal deserialisation differences.

Start the application locally

The generic argument on runApplication identifies the configuration root. The star in *args spreads an array into a vararg call. With proxyBeanMethods disabled this configuration class does not need subclassing to intercept configuration-method calls. There are no proxy-based transactional annotations in this project. Introducing Spring AOP on a final concrete Kotlin class later requires attention to proxy type, the Kotlin Spring compiler plugin or explicit openness. Self-invocation inside the target can still bypass proxy advice.

With Docker and Compose installed, run from the extracted project root. The first build compiles and tests the app. Compose starts a local PostgreSQL and waits for its health check. On first startup Flyway applies the supplied schema. The container guide dissects the image and volume.

The fixed ID lets you reproduce a replay. Starting with an unused ID, the two statuses should be 201 and 204. The final JSON contains GILT and 10125. A repeated lab against the same database starts at 204 because a successful previous run already owns the key. Generate a fresh UUID if you need the create path again.

Evolve the contract without leaking implementation details

The wire DTO serves client compatibility. The domain object enforces economic constraints. The store returns business outcomes independently of HTTP. If the price scale changes from hundredths to ten-thousandths, silently reinterpreting ticks would change historical prices and turn retries into conflicts. Introduce an explicit schema or instrument scale and specify how old identifiers retain their original meaning.

MVC plus JDBC fits an existing Spring estate and blocking drivers. Ktor gives a smaller coroutine-oriented HTTP stack and explicit plugin wiring. WebFlux is appropriate where a nonblocking chain can be maintained end to end. Select based on the dependencies you must call, the concurrency you can sustain and the team's operating experience. A framework switch leaves the idempotency contract and database invariant to solve.

The supplied API binds to loopback through Compose and the Kubernetes service is internal. Before offering it to production clients, define client identity, authorisation for the relevant instrument or tenant, and TLS termination. In a multi-tenant system the idempotency key generally needs tenant scope as part of its unique constraint. Checking tenant identity only in the HTTP layer would leave the stored key globally shared.
