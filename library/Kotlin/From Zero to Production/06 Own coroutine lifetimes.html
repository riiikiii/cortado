Separate waiting, scheduling and ownership

Two independent price feeds take nominally 20 ms and 150 ms. The caller needs both results within one deadline. Start with Concurrent.kt and run quotes.Concurrent as in chapter one. The waits simulate asynchronous clients so the experiment needs no external endpoints.

A suspending function can pause and later resume with its local state preserved. Calling one does not by itself create a task, assign a new thread or overlap two calls. In this example async creates a child coroutine and returns a Deferred, a handle to its future result. Both children are created while constructing the list. awaitAll suspends the parent until the results are available or a failure intervenes. Returned values follow the order of the handles. The finally blocks report the order in which cleanup ran, which can differ.

runBlocking bridges a conventional main function to suspending code and blocks the calling thread until its scope completes. delay suspends without occupying that thread for the duration. Replacing delay with Thread.sleep in this particular runBlocking context can hold the one thread on which both child tasks and deadline processing depend. Adding suspend to a JDBC function leaves the JDBC call blocking.

Read the deadline as a timeline

Nominal time Long budget Short budget
0 ms Both children launched Both children launched
20 ms A supplies 10125 and closes A normally completes
60 ms Parent still waiting for B Timeout cancels pending work; B runs finally
150 ms B supplies 10130; list contains both ticks Parent has returned the fallback after cleanup

Timings describe intent, not a real-time promise. A loaded machine can delay scheduling, including timeout delivery. Observe a list of two ticks for the two-second budget under ordinary conditions, then the word deadline for the shorter budget. Try making A the slow child. Output order of the finally messages can change while the successful list still has A first. This distinguishes completion order from data order.

Decide what failure should cancel

Use coroutineScope for related work that must succeed as one operation. An ordinary failing child cancels sibling work in that scope and the failure propagates. With supervisorScope, sibling failures can be isolated, but an exception you allow to escape the supervisor block still ends that block. To return partial data, define a result for each feed and handle expected feed-specific failures inside the child. Let cancellation propagate. Catching every Throwable or blindly using runCatching around suspending I/O can consume a CancellationException that the caller depends on.

IO is a dispatcher intended for blocking work. Moving a call there can protect an event-loop thread. It does not make the operating-system call cancellable or expand database capacity. Bound concurrency to the client pool, set driver-level timeouts, and decide how to surface queueing. Eight database connections cannot execute fifty independent queries simultaneously. In the service below Spring MVC and JDBC deliberately use a consistent blocking model. The coroutine example is appropriate for concurrent upstream calls with compatible clients.

Flow when there is more than one result

A cold flow built with flow runs its producer for each collector. A slow collector normally slows emission in a sequential pipeline. A buffer lets producer and consumer overlap within limits. Conflate allows intermediate values to be skipped when the consumer lags. That can suit a live best-price display. It changes the meaning of an audit feed that must retain every observation. StateFlow represents current observable state and a new subscriber sees the current value. Durable history and replay after process loss require persistent storage.

For a concrete variation, let B wait indefinitely using awaitCancellation. The long-budget call then also times out. The process should exit after both calls because each child belongs to its caller's scope. Launching a background task in a process-global scope instead would detach its lifetime and failures from the request. That ownership choice matters more than the spelling of async.
