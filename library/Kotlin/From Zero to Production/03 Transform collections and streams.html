Decide when work happens

Walkthrough.kt has three records in memory. It needs the best price per instrument and the number of rejected records. Trace each transformation before optimising it.

Stage Value Work performed
lines GILT,10125 · GILT,10130 · BAD,? The command-line adapter chooses its input.
mapNotNull Two Quote instances The parser runs once for each of three lines.
groupBy GILT → a list of two quotes A map stores a group of elements for each key.
mapValues GILT → 10130 maxOf compares the ticks in the group.

map preserves one output per input, including a nullable output. mapNotNull removes null outputs. flatMap expands an input into several outputs. associateBy keeps one value per key, replacing the earlier value on duplicate keys. That last behaviour loses information in a price feed. Reverse the first two GILT lines and the last arrival becomes the lower price. A maximum should be independent of that order.

Replace retained groups with an accumulator

The loop maintains an invariant. After any prefix of the input, each entry is the highest valid price seen so far for its symbol. On first sight of GILT the map contains no value. After 10125 the map has one entry. Reading 10130 replaces that entry, while an invalid record leaves it alone. Both algorithms use linear work in the number of lines. The grouped implementation retains every valid observation. The accumulator needs one entry per distinct instrument, plus the returned copy. For a bounded list the grouped operation can be easier to adapt when the next request asks for all observations in arrival order.

The extension function toMap() returns a separate read-only view of the copied entries in this use. It does not recursively freeze arbitrary objects. Here keys and values are immutable. Local mutation is useful because no other caller can observe a partially accumulated map.

Watch a lazy pipeline stop early

Only the first two strings appear in the diagnostic output. Intermediate sequence operations build a plan. The terminal consumer asks for one value, discards the first malformed input and stops at the next line. An eager list map would parse every line before firstOrNull could run. Repeating a terminal operation can repeat the work. A sequence backed by a one-shot iterator might only allow one traversal. Materialise intentionally when repeatability matters.

Sequences can reduce intermediate allocations. They can also add iterator and lambda overhead to small, simple loops. Measure the real pipeline before changing it for speed. Sorting or grouping generally still needs retained state even if the upstream source is lazy. A Kotlin Sequence iterates synchronously on its caller's thread. It conveys neither parallel execution nor asynchronous delivery.

Ownership of external resources

The resource lifetime encloses the terminal operation. Returning the lazy line sequence from inside this lambda would let iteration escape the open reader. The file could be closed before the first item was consumed. The same rule applies to cursors and network streams. Return the computed result or make ownership of closure explicit in the API.

For a variation, feed a million observations of GILT into both implementations. The number of groups remains one while the group's list grows to a million. If the requirement changes to “retain the last 100 observations per symbol”, a maximum alone loses the information needed to evict an old high. The shape of retained state follows the question you need to answer.
