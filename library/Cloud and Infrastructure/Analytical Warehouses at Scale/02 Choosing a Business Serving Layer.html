How a shortlist changes with the question

Snowflake for a governed SQL estate. Give reporting and research separate warehouses. If one uncached historical query spills heavily, try a larger warehouse and inspect its query profile. If each query is already fast in isolation but 100 arrive together and queue, trial concurrent clusters or scheduled capacity. Clustering a frequently filtered large table can reduce partitions scanned, while reclustering incurs ongoing work. Validate a representative new filter value after resume. An identical cached dashboard query can conceal both poor pruning and startup latency.

Fabric for a Power BI estate. Import materialises a model during refresh and makes query latency largely a model question. DirectQuery pushes work towards the source on interaction. Direct Lake can load needed Delta columns into memory for the semantic model. Framing, memory headroom, model design and cardinality matter. Direct Lake on SQL endpoints can fall back to DirectQuery in specified cases. Direct Lake on OneLake has different behaviour. Record the exact model mode, security configuration and observed execution path for each benchmark. A fast SQL query does not establish a fast DAX measure. Materialising the expensive history join once can matter more than changing SQL engines. Liquid clustering is a layout option for suitable tables and runtime versions. Choose keys from measured selective predicates and account for optimisation work. Connect the lake to the serving mart

Give the publisher a durable input tuple: batch ID, previous snapshot, new snapshot, event-sequence upper bound and metric-definition version. The landing job archives source events before acknowledging progress. An orchestrator seals the batch after the Iceberg commit and records its snapshot ID. A SQL job reads that specific snapshot and emits a staging result at the agreed report grain. The loader streams the staged rows into Postgres using a bulk operation such as COPY. Compare row counts and per-currency totals to the source manifest. Promote only a validated release.

At small grain, compute a complete fresh mart per publication. At larger grain an incremental policy must name every affected key. Suppose A moves from GILT to CREDIT on the same day. Reading only the new value identifies CREDIT but misses GILT. Use a before-image or the prior snapshot to collect both old and new keys. Recompute their totals from the new pinned cut. For a removed final trade, explicitly remove the old group or publish a zero according to the reporting contract. A missing group in an incremental file cannot itself delete a stale row. If the serving tables hold complete versions, copy forward unchanged groups or implement a versioned lookup that resolves their previous rows. A head pointer to a sparse delta would hide unaffected books.

Periodically reconcile hot totals to a pinned lake snapshot at the same source watermark. This adds a second implementation of the metric. When a managed database becomes a warehouse project

A single Postgres server can parallelise eligible scans. Range partitioning lets pruning skip months and simplifies retention. A B-tree serves selective lookups, BRIN can cheaply summarise large physical ranges correlated with time, and neither accelerates an unfiltered sum of most values by making the rows disappear. Every additional index adds write and maintenance cost. Read replicas can spread independent queries and isolate the primary, but a single query generally executes on one replica and asynchronous replay introduces lag. Read the head and data from the same consistent endpoint. HA standby and readable replica capabilities vary by managed service and deployment. Sharding by portfolio helps tenant-scoped reads. A cross-portfolio aggregate now needs fan-out, partial sums and a common publication cut across shards. Add a lake when retention, replay or scans earn it. Add a serving replica or analytical engine only when its measured benefit covers the extra publication path.

Protect the number at every boundary

Tie the published batch to input offsets or object manifests, snapshot IDs for each source table, valuation rules and the security-policy version. Joining two individually consistent snapshots still requires a shared business cut. Test a book transfer between two permission domains with ordinary viewer accounts. Source entitlements may not survive copying to another engine or exporting query results. Use least-privileged writer and reader roles, scope result buckets and encryption keys, and enforce equivalent row policies in BI, SQL, exports and API caches. Include identity or entitlement scope and publication ID in cache keys.

Set recovery objectives separately for source history and business serving. Keep enough versioned input to rebuild a lost mart. Exercise a restore in an isolated destination, reconcile Â£60 and its as-of time, repoint a test reader and measure elapsed time. A replica can propagate a bad release. A reproducible version and a verified last-good pointer give operators a distinct rollback route. Preserve previous versions long enough for pinned reports to finish.

Which pair deserves a pilot?

For S3-first history and a small fixed set of hot aggregates, pilot Athena/Iceberg plus indexed Postgres or a BI model. For many unpredictable interactive groupings, pilot a managed analytical warehouse with equivalent summaries and direct drill-down. For Power BI-heavy organisations, include Fabric with the actual semantic model. For substantial existing Delta/Spark transformation, include Databricks SQL. Trial self-operated Trino when connector flexibility or sustained warm capacity matters enough to staff it. A shortlist of two comparable end-to-end designs is easier to evaluate honestly than nine isolated SQL stopwatches.
