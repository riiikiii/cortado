Foundations / 01

Where the SQL comes from

Trace one repository call through the Java stack.

An object-relational mapper (ORM) translates between an object graph and relational rows. The useful question when reading Java is what work does this line cause, on which connection, and when? A call can issue SQL immediately, queue a write, or return an object already in memory.

LayerIn the fill serviceWhat it owns
Spring Data JPAorders.findById(id)Repository implementation, derived query methods and paging conventions.
Jakarta Persistence (JPA)EntityManager, @EntityStandard contract for identity, mapping, queries and lifecycle.
Hibernate ORMPersistence context and action queueImplements JPA, tracks changes, generates dialect-specific SQL and chooses when to flush. EclipseLink is another provider.
JDBC + connection poolPostgreSQL driver + HikariCPThe pool lends connections. JDBC sends statements and binds typed values.
PostgreSQLConstraints, locks, plans and commitsDecides physical access paths, arbitrates concurrent writes and enforces data integrity.
Coming from EF Core or SQLAlchemy

Think of EntityManager as roughly analogous to DbContext or Session. A JPA persistence context gives one Java identity per entity key within its scope. A DataSource is closer to a connection factory or pool. It belongs at application scope.

Predict • Two find() calls for the same ID in one persistence context. How many objects?

One managed instance. With an initially empty context, default locking and no second-level cache, expect one SELECT. A JPQL query can still execute SQL even when its result maps back to that same instance.

Foundations / 03

Design the mapping

Start with the foreign key, the domain invariant and the exact numeric type.

trade_orderPK · idquantity · filledversion
1 ⟷ 0…N
execution_fillPK · idFK · order_idexecution_ref · price · units

A fill belongs to exactly one order. An order can exist before any fill arrives. The database stores the relationship once, in execution_fill.order_id. Java can navigate from a fill to its order with a single @ManyToOne. The lab deliberately leaves the reverse collection unmapped. A blotter can query fills directly without materialising an entire execution history.

If a parent really needs a collection, add @OneToMany(mappedBy = "order"). The string is the Java field name on ExecutionFill. In a bidirectional model, an addFill helper must also set fill.order. Changing only the inverse collection can leave the foreign key unchanged.

ChoiceUse it whenWatch for
UUID / sequence / identityUUIDs can be generated without a database round trip. Sequences suit compact numeric keys.Database identity generation can force early inserts and restrict Hibernate insert batching. Align pooled sequence allocation with database increment settings.
BigDecimal → NUMERICPrices require a declared scale. Construct from a decimal string and define rounding explicitly.The sample rejects extra non-zero decimal places. For multi-currency amounts, persist a currency code alongside the value.
Instant / LocalDateUse Instant for an event instant and LocalDate for a settlement date.PostgreSQL timestamptz preserves an instant. Store the zone separately when business logic needs the original zone.
@Enumerated(STRING)A small domain state can use a readable stable identifier.Renaming a constant needs a migration. An AttributeConverter can map a stable external code.
@Embeddable / @EmbeddedIdEmbed a value object, or represent a real composite primary key.Composite key equality must reflect its columns. Keep ordinary embeddables free of independent lifecycle.

Entity design and Lombok

Place @Id on a field to select field access. Keep a public or protected no-argument constructor and leave entities proxy-friendly. Avoid @Data on entities. Generated toString or equality methods can traverse lazy associations, recurse through a graph or change a hash after ID assignment. DTO records are a cleaner fit for structural equality.

Cascade and deletion

Cascade PERSIST if a parent is responsible for creating its children. Use orphanRemoval only if removing a privately owned child from the relationship really means deleting its row. A fill is an audit record in this example. A reversal would be a new business event. Never cascade REMOVE from a fill to a shared order or instrument.

Working with data / 04

Read the persistence context

A Java assignment, a SQL UPDATE and a committed transaction are three separate events.

StateEntryWhat happens next
Newnew TradeOrder(…)No row is implied. persist() registers the object and schedules insertion.
Managedpersist(), find(), query, or the return value of merge()Changes to mapped fields are tracked. SQL is coordinated at flush.
Detacheddetach(), clear(), or close the contextMutations are ordinary Java operations. merge() copies state onto a managed instance and returns it.
Removedremove(managedEntity)Deletion is scheduled. Constraints or cascades can affect whether flush succeeds.

Flush sends pending SQL to the database. The transaction can still roll back. Under AUTO flush a query may trigger synchronisation before commit so its result reflects relevant pending changes. Calling clear() before flush can discard pending changes. A failed flush should normally end the unit of work with rollback.

JpaRepository.save() usually selects persist or merge from its newness strategy. Assigned identifiers deserve care. A nullable wrapper @Version or Persistable.isNew() may be appropriate. If using merge, continue with its returned reference. For an update command, load the row and apply permitted changes. Merging a partially populated detached entity can overwrite columns the caller never intended to edit.

Predict • You call flush(), then throw a runtime exception out of the transactional service. Does the fill survive?

With ordinary Spring transaction defaults, the transaction rolls back. A SQL statement in a log establishes that work was sent. Only a successful commit establishes durability.

CRUD without the repository abstraction

This mechanics exercise creates and removes an order with no child rows. For a persistent trading record, model cancellation as a state transition with an audit trail. A foreign key prevents deleting a parent with live fills unless you explicitly specify another deletion policy.

Choose a query by result shape

Write the query around what the caller needs to display or change.

QuestionFirst choiceReason
Does this execution reference exist?existsByExecutionRef(String ref)A derived method states the predicate concisely. Keep a database unique constraint for concurrent arrivals.
What fills belong to this order?JPQL + typed DTOSelect just the fields for the blotter and bind the order ID.
Which filters are enabled today?Criteria API / Spring Data SpecificationCompose optional predicates and joins as data. Add a predicate only when its filter is present.
What is the running executed quantity?Native SQL or jOOQWindow functions, CTEs and vendor features often read more clearly in SQL.

Binding separates query structure from values and lets the driver preserve types. Column names and sort directions are structural. Map requested sort keys to an allowlist of known attributes. getResultList() returns an empty list when there are no matches. getSingleResult() expects exactly one row and signals missing or duplicate rows with exceptions.

Dynamic filters with the Criteria API

Use jakarta.persistence.criteria.Predicate here. A generated static metamodel replaces string attribute names with compiler-checked references. Spring Data wraps the same predicate-building model in Specification and JpaSpecificationExecutor.

Bulk updates change the rules

A JPQL UPDATE applies directly to matching rows. It bypasses ordinary per-entity dirty checking, callbacks and automatic optimistic version handling. Flush pending changes first, execute the update within a transaction, and clear or refresh affected managed objects. For one guarded write, include the expected version in the WHERE clause, increment it explicitly and check that exactly one row changed.

Working with data / 06

Make the cost of fetching visible

Explore the difference between result rows, SQL statements and Java objects.

Suppose a page reads fills and then displays each owning order’s symbol. With cold caches, lazy to-one associations, no batching and one distinct order per fill, iterating the page triggers one root query plus one query per order. Repeated fills for the same order can reuse a managed instance.

A fetch join initialises the association for this query. An entity graph expresses which attributes must be available, leaving SQL strategy to the provider. A DTO projection fits a read-only page especially well. Changing all associations to EAGER can still produce secondary selects. JPA defaults to eager for to-one and lazy for to-many; explicitly choose the fetch plan for each use case.

Why a single query can still be expensive

Fetching 10 orders with 8 fills and 5 independent tags each can yield 400 SQL rows when both collections are joined. Parent de-duplication in memory does not undo wire traffic. Hibernate also rejects some simultaneous bag fetches. Page ordered parent IDs first, load associations for those IDs separately, then restore the original order.

Read past the first page

Offset paging is simple for a small result. Large offsets make PostgreSQL walk past discarded rows. For the fill list, a unique, immutable execution reference can act as a cursor. Choose this only if lexical reference order is the desired display order. For time order use a timestamp plus a unique ID tie-breaker and a matching composite index.

Omit the cursor predicate for the first page. Return the 50th displayed reference as the next cursor. Spring Data Page can run a count query to supply totals. Slice is useful where the caller needs only “is there another page?”. A stable sort alone cannot freeze membership across transactions.

Correctness / 07

Draw the transaction boundary

Record the fill and update the order as one business operation.

An external call enters the Spring transaction proxy. With the usual REQUIRED propagation, the service joins the caller’s transaction or starts one. The repository and injected EntityManager participate in the same transaction. The managed order changes and the new fill becomes persistent. If the unique execution reference or version check fails, the entire booking rolls back.

Boundary decisionConsequence
Self-invocationCalling this.record() inside the same class bypasses the standard proxy. Put the transactional entry point on a bean invoked by another bean, or use TransactionTemplate.
Checked exceptionsSpring normally rolls back on unchecked exceptions and Error. If a checked business exception must abort the booking, configure rollbackFor or use an explicit policy.
readOnly = trueDocuments intent and permits optimisations. Enforcement depends on the transaction manager and database.
REQUIRES_NEWSuspends the outer transaction and commits independently. It can require an additional pooled connection while the outer one remains held.
Async or parallel workA thread-bound transaction does not cross into arbitrary worker threads. Start a fresh unit of work and never share a real EntityManager between threads.
Publishing FillBookedTo survive a crash between database commit and message publish, insert an outbox row in the booking transaction. A separate publisher retries delivery. Consumers deduplicate by event ID.
Diagnose • A controller serialises a detached fill and touching order.symbol fails. Where should the fix go?

Choose the response shape at the service boundary. Query a DTO or initialise exactly the required association while the context is active. Returning a DTO also prevents serialisation from triggering an unbounded walk through the object graph.

Correctness / 08

Handle two fills arriving together

Work through a lost-update timeline and choose the recovery policy.

TimeTransaction A · fill 60Transaction B · fill 50
① ReadSees 0 / 100, version 4Sees 0 / 100, version 4
② Validate60 fits the remaining 10050 fits its own snapshot
③ WriteUpdates where version = 4, commits 60 / 100, v5Update using version 4 affects zero rows after A commits
④ RecoverIts fill is durableRoll back, reload 60 / 100 in a new transaction. The remaining 40 cannot accommodate 50.

A version column protects against an intervening update to the same versioned row. It cannot by itself enforce an invariant spanning unrelated rows. The lab updates the parent on every fill, giving contending bookings a common row. If you only insert child rows, the parent version does not automatically protect the sum.

Optimistic, pessimistic or atomic SQL?

Optimistic locking works well when collisions are infrequent. For sustained contention, load the order with em.find(TradeOrder.class, id, LockModeType.PESSIMISTIC_WRITE) inside the transaction before inspecting the remaining quantity. Competing writers wait, which consumes connection time. Acquire multiple locks in a stable order and set a lock timeout.

For the atomic SQL path, check that one row changed and insert the corresponding fill inside the same transaction. A zero count can mean missing order or insufficient room. Avoid continuing with an old managed copy of the order after this native update.

Duplicate execution or genuine conflict?

A unique execution reference prevents double booking. The lab surfaces the duplicate as an error. For an idempotent API, handle the rolled-back attempt outside its transaction, read the existing fill in a fresh transaction, and compare order, units and price. An identical replay can return the previous success. A different payload under the same reference is a data-quality exception.

PostgreSQL READ COMMITTED usually takes a fresh snapshot per statement. REPEATABLE READ holds a transaction snapshot, and SERIALIZABLE can abort transactions to preserve a serial execution order. Retry a transient serialization failure or deadlock from the transaction boundary with bounded backoff. Recheck all business conditions. Keep side effects outside the retry loop or make them idempotent.

In production / 09

Tune from evidence

Measure what the database and the connection pool actually did.

SymptomMeasure firstCandidate change
Slow blotterCount SQL statements and rows returned for 1, 10 and 100 fills.Replace accidental N+1 traversal with a projection, join fetch or measured batch plan.
One slow statementInspect EXPLAIN (ANALYZE, BUFFERS) on representative data. Compare estimated and actual rows, sorts and buffer reads.Match index order to predicate and ordering. ANALYZE executes the query. Use a safe test database for modifying statements.
Connection timeoutsPool acquisition latency, active connections, transaction duration, blocked sessions.Move external calls outside transactions. Budget pool connections across replicas and jobs against the database limit.
Large ingestion heapPersistence-context size, batch size, round trips and commit time.Use JDBC batching with periodic flush/clear. Separate transaction chunks if partial completion and restart are acceptable.
Stale dataIdentify first-level context, optional second-level entity cache, query cache and external writers.Cache mostly stable reference data deliberately. Specify expiry or invalidation for writes outside Hibernate.

Try spring.jpa.properties.hibernate.jdbc.batch_size=50 and measure driver-level batching. Flushing every 50 entities bounds memory but leaves a single transaction open. For restartable imports, commit chunks and their checkpoints atomically. For very large PostgreSQL loads, benchmark COPY into staging followed by a set-based merge.

Schema evolution while old and new versions coexist

To add a compulsory external identifier, add a nullable column first. Deploy code that populates it, backfill old rows in bounded batches, verify coverage, then enforce NOT NULL after old writers are retired. Ship Flyway scripts in order and keep previously applied migrations immutable. Use a migration role for DDL and limit the runtime role to the operations it uses.

Test the behaviour at the boundary

Prove reloads, rollbacks, uniqueness and contention on PostgreSQL.

A repository test over an in-memory dialect can miss PostgreSQL type, locking and index behaviour. Run migrations against an isolated PostgreSQL instance, for example a Testcontainers PostgreSQLContainer. With Spring Boot 3.5, a test-scoped spring-boot-testcontainers dependency enables @ServiceConnection; also include spring-boot-starter-test and the Boot-managed Testcontainers PostgreSQL and JUnit Jupiter modules.

Leave this test method outside a surrounding test transaction so each service call owns its commit. For Maven Surefire default discovery, name the class BookingTest or run mvn -Dtest=BookingIT test. The sample CommandLineRunner also runs on startup. Unique test references keep the fixture independent.

Why might a repository test pass even though the write fails in production?

A rollback-only transactional test can end without forcing a flush or commit. An immediate find() may also return the original managed object. Flush and clear to test a database round trip, and use a real commit for deferrable constraints or after-commit behaviour.

Field reference / 11

Choose the right abstraction

Match the programming model to the work and keep transaction ownership explicit.

ApproachGood fitWhat you own
Hibernate + Spring Data JPATransactional aggregates, versioned edits, domain navigation.Mappings, fetch plans, transaction boundaries and emitted SQL quality.
Jakarta Persistence directlyExplicit persistence operations or code shared across providers.EntityManager lifecycle and transaction demarcation in a standalone app. In Spring, use the injected transactional proxy.
Spring Data JDBCSmall aggregate roots with simpler persistence semantics.Aggregate boundaries and write behaviour. There is no JPA-style persistence context or lazy-loading model.
jOOQTyped SQL, complex analytics and vendor features.SQL shape, result mapping and schema-driven code generation.
MyBatis / JdbcTemplateExisting SQL estates, bespoke batch updates and explicit row mapping.Statement design and mapping. JDBC itself also requires careful resource handling.

A trading service can book fills with Hibernate and build a reconciliation report with SQL. If the two paths must observe the same uncommitted work, use a compatible Spring transaction manager with the same DataSource, flush before a JDBC read, and refresh or clear stale entities after JDBC writes.
